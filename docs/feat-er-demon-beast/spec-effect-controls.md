# 游戏动作与效果驱动变身

## 已确认需求

用户明确指出：F6/F7是独立键盘入口，不能作为正式变身操作；期望真实游戏按键与动画通知衔接，通过检测SpEffect驱动变身，使手柄也可用。这是正式输入接入需求，不是F6/F7偶发失效报告。

保留已确认的形态优先级、动作结束后退场、先清理后切换、持效不重进、效果消失不解除、独立时长、-1仅取消计时且保留战技原版解除等规则。

## 已确认的增量

- 推荐进入与解除使用不同效果：进入效果出现在玩家本体时请求对应形态；解除效果出现在玩家本体或当前受控兽体时请求解除。其他实体的同名效果不能触发。
- 解除优先于同次观察到的进入，取消尚未开始的切换。常态下解除信号不产生变身；活动期解除等待动作与退场；进入阶段解除中止进入；清理阶段不再次生成实体。
- 进入、解除均按效果从不存在到存在触发；一次持续效果只产生一次请求。效果消失不解除，移除再出现可产生新请求。未知/失败的读取不能视为消失。
- F6/F7保留为可选调试入口，正式配置默认关闭。道具、战技或动画如何施加所选效果需要明确资源接入点，不能把DLL可检测效果等同于已完成游戏动作接线。
- 不采用单效果切换；进入与解除效果不得相同，避免方向歧义。
- 效果ID尚未提供；禁止猜测现有ID的用途或启用未经接线的占位ID。

## 人工验证增量

沿用已有有效单机场景、准备好的c0010资源和3秒进入/恢复、0.25秒触发采样目标。由用户操作游戏，代理不启动游戏、不读取活体进程。输入前提是指定动作确实把效果施加到约定对象，并保持到至少一次有效观察；极短脉冲的可靠捕获不由现有轮询保证。

| Case | 输入和预期 |
|---|---|
| EC-P01 | 关闭调试热键；键鼠与手柄分别执行同一游戏动作，玩家本体出现进入效果，进入对应形态；无需F6 |
| EC-P02 | c0010空闲和攻击期间分别施加解除效果；常规解除等待动作和退场，不截断攻击；无需F7 |
| EC-P03 | 解除效果分别来自本体、当前受控兽体、无关NPC；前两者有效，第三者无效 |
| EC-P04 | 两信号同时出现，解除优先且取消切换；持续存在不重复执行；移除再施加才重新触发 |
| EC-P05 | 无限形态不执行解除动作时观察60秒；再执行解除动作；另测原版战技仍自行解除 |
| EC-P06 | 关闭调试热键时F6/F7无变身作用；显式启用后保留原调试职责；原输入映射与连按翻滚回归 |

用户回复“两个效果分别进入/解除，ID暂未确定，最好能在配置里自定义”，确认双效果方案。ID作为用户配置输入，不要求编译时确定；没有实际ID与游戏施加动作时，仅交付检测能力及配置说明，不宣称已完成手柄实机接线。未接线的旧测试配置保留显式调试入口，正式配置默认关闭调试键。本规格基线化1.0，补充既有Spec-custom-forms1.0；原Probe时限/清理规则不变。
