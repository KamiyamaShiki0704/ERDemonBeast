# 多形态配置阶段

用户于当前会话确认按形态定义身份、SpEffect 自动/按键两种模式、时长、锁定四向选项和输入映射，并确认选择冲突、Probe 语义及无限时长的战技解除规则。本规格基线为 1.0。

## 范围与规则

- CF-001：配置包含多个命名形态，各自定义角色与参数、触发效果/模式、优先级、持续时间、镜头、四向选项和动作映射。默认形态为当前 c0010，F6/F7 和 15 秒行为保留。
- CF-002：只读取玩家本体上的效果。自动形态在效果新出现时请求进入/切换；手动形态在匹配效果存在且按 F6 时请求进入/切换。无效果匹配时 F6 选择默认形态。同优先级的有效形态配置拒绝加载，避免顺序歧义。手动解除优先于同帧进入。
- CF-003：解除/到期/战技返回后，仍持续存在的自动效果不立即重进；该效果先消失再出现才重新触发。效果自然消失不自动解除当前形态。
- CF-004：活动中选到另一形态时，先等待当前动作与退场，再完成旧兽体清理，然后才生成下一形态。等待期不叠加新请求；F7 取消尚未开始的新形态。新形态加载失败恢复可操控本体，禁止重复自动重试。
- CF-005：有限时长从可操作开始计算，允许正数秒；-1 只取消到期计时，保留战技原版解除和 F7 手动解除。0、其他负数、非有限数值拒绝。无限时长不屏蔽异常恢复。
- CF-006：玩家语义输入映射轻击、重击、防御、战技、闪避及已适配连段目标；沿用游戏按键绑定。只允许适配器已支持的动作，不强行把 c0000 脚本用于 NPC。direct_c0000 模式预留并明确拒绝运行。不同角色 ID 仍需要配套行为/动作资源，不保证仅改 ID 即可使用所有映射。
- CF-007：默认配置保持现有 c0010 行为；多形态配置错误在安装游戏任务之前明确报错。切换场景、角色死亡/所有权丢失等沿用紧急恢复，仍优先清理且不得创建第二个受控实体。

## Probe 输入与预期

人工测试沿用现有单机平地场景与用户存档；代理只做离线验证，游戏由用户执行。语义前提为各测试形态资源与参数已准备，效果由用户自己的手段施加/移除。可先用同一 c0010 的不同配置验证路由；不能据此声称另一模型已适配。

| Case | 输入与预期 | 时限与人工边界 |
|---|---|---|
| CF-P01 | 默认无效果 F6 -> c0010；分别施加自动/手动效果，按相应规则进入；同时匹配时优先级高者胜出 | 触发采样目标 <=0.25秒，场景有效时3秒内可操作；人工确认实际身份 |
| CF-P02 | 两形态分别设5秒/15秒，进入完成后计时；提前F7解除 | 到期触发误差<=0.25秒；等待当前动作及退场后3秒内恢复；人工观察无攻击截断 |
| CF-P03 | -1形态持续60秒，中间移除效果，再F7；另一次进入后执行原版自行解除的战技 | 60秒窗口内无计时解除，不以有限观察证明永久；F7等待动作及退场；战技按原版通知解除，不重复播放退场；异常恢复另算 |
| CF-P04 | 自动效果保持存在，到期/手动解除，观察5秒；移除再施加 | 不立即重进，重新出现后才可触发；F6显式请求可再次进入 |
| CF-P05 | A活动中触发B；等待期间F7另做一轮取消；B参数/资源不可用另做一轮 | 始终最多一个受控兽体，旧清理确认后才生成B；失败恢复本体、不无限重试；恢复时限沿用3秒，故障保留既有保护 |
| CF-P06 | c0010交换轻/重击映射，禁用一个输入，再测试连续翻滚和F7；请求未适配动作/direct_c0000 | 已映射动作1秒内响应，现有窗口仍生效；无效配置明确拒绝；伤害、蓄力、完整c0000脚本复用不作为本轮通过项 |

自动检查覆盖配置拒绝、时长、竞争选择、自动触发重装、切换清理次序与真实HKS映射；最终游戏效果由人验收。不同形态真实模型、命中/伤害、联机、切图、完整视觉特效不由配置测试代替。

## 本轮确认记录

用户已回复“按这组规则实现”，确认优先级、自动效果重装、切换清理、F7取消、效果消失不解除，以及上述 Probe 时限/排除项。随后回复“按照1处理”，确认 -1 只取消计时，战技仍按原版解除，F7也能解除。另报告 F6/F7 使用“有些奇怪”，具体表现待补充；未据此擅自改为单键开关。
