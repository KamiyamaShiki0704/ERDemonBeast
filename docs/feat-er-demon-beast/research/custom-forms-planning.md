# 多形态扩展：当前实现边界与候选结构

这是基于本地源码的规划记录，不是已经实现的配置接口。

## 当前事实

- `src/native.rs::Config` 是单形态配置，包含 chr_id、npc_param_id、npc_think_param_id；不支持形态表或 SpEffect 路由。
- `src/session.rs::ACTIVE_DURATION` 固定 15 秒，当前不存在 -1 无限时长分支。
- `native.rs::update` 通过 F6/F7 生成进入与还原请求；当前未根据 SpEffect 生成请求。
- 当前输入接管将 debug manipulator 绑定到独立兽体，保留玩家本体；并非直接在兽体上运行完整 c0000 行为/动作脚本。
- 原 NR 研究指出 c0010 自身依赖 c9997 行为和脚本族；源作能控制魔兽不能证明 ER 中可直接加载这些规则。

## 给资源接入阶段保留的边界

1. 形态定义：稳定的形态键、ER 目标角色和对应参数、动作/行为资源、持续时间、输入规则配置。
2. 触发选择：将本体 SpEffect 与手动输入转成进入、切换、还原意图；不要让兽体自身常驻效果意外触发选择循环。用户已确认按形态配置自动/手动两种触发模式。
3. 生命周期：仍由统一事务持有本体快照和兽体所有权；不得为每个形态复制一套原生清理流程。形态切换必须经过旧实体清理确认。
4. 动作适配：玩家语义输入（轻击、重击、按住/松开、方向和连段窗口）与形态可执行的动作/行为分开。复用键位不代表可以直接使用 c0000 的 HKX、TAE、武器行为或所有 HKS 接口。

建议将配置中的 -1 在校验后表达为“无到期时间”，不使用超大秒数模拟；其余值需为有限正数。接管成功后固定本轮形态与计时配置。已有 15 秒行为可保留为默认兼容配置。

## c0000 规则的证明层次

- 输入习惯：尽量沿用游戏当前绑定的语义操作，避免仅写死物理键盘键而忽略手柄/重绑定。
- 招式决策：轻重击、蓄力与连段是可规划的映射目标，需要逐个建立动作和状态对应。
- 完整脚本复用：是否能直接执行玩家现有 c0000 脚本、是否兼容既有招式 Mod，必须验证脚本对 PlayerIns、装备、武器、骨架、行为事件和引擎接口的依赖。不能从现有 NPC 接管测试推出这一层兼容性。

用户已确认两种模式均保留扩展点，先实现输入与招式映射。完整脚本模式在未验证前必须标为不可用或明确拒绝配置，不能静默回退并假称已复用脚本。

本轮仅记录后续需求及本地源码边界；未修改 DLL、配置解析器或游戏文件。具体默认语义与验收由 requirements-custom-forms.md 收敛后形成正式 Spec。
