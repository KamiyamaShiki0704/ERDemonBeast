# c0010 行为 v7 / DLL 0.3.1 人工测试

本轮修正连按闪避时重复请求同一活动节点可能卡住输入的问题；保留 v6 已人工确认的退场修正。DLL 0.3.1 和 Behbnd 不变。离线检查通过；代理没有启动游戏。

## 配置

DLL 同目录 er-demon-beast.toml：

```toml
locked_four_way_movement = false
```

false（当前默认）：使用原版魔兽朝向与移动规则。true：锁定时按四方向请求动画，但缺少对应动画的方向不会执行。当前 c0010 有前进 HKX，没有独立的后/左/右 HKX，所以打开开关本身不能补出这些动画。改配置后完全重启游戏。当前开关作用于当前形态，后续多形态版才分形态保存。

## 先测本轮连续闪避修正

1. 完全重启，F6 登场完成后快速点按翻滚 5～8 次，再松键。兽体不能永久定住；随后应能移动、轻击和重击。分别在锁定/未锁定下测试。
2. 单次闪避后，在正常衔接窗口接轻击或重击；不能因防重入把原本的衔接禁掉。闪避仍活动或退出混合时的重复闪避不会重启动画，窗口前短按不保证一定缓存。
3. 连续闪避后按 F7，再单独测试接近 15 秒到期时闪避；应完成动作、播放退场并恢复，不出现 8 秒保护超时。恢复后再次 F6 确认可重入。

新日志 input=5 deferred=step_still_active 表示拦下了上一闪避尚未退出时的重复请求；随后有效的新请求仍应出现 fired=6000。若仍卡住，请先松开全部动作键，再试移动/轻击/F7，退出后收集日志。无需代理运行游戏。

## 已通过的退场修正回归

重新启动后在平地 F6，登场完成后站立按 F7。应能看到短退场，再恢复本体；不能刚开始退场就恢复，也不能停住 8 秒。重复三次，之后再检查普通重击中 F7 和到期解除。日志 animation=outro:true:true 表示混合中两个节点同时活动，不再算完成；仅 outro:false:true 才能确认正常退场。战技保持其自身通知点直接解除，不追加完整第二段退场。

## 其余回归顺序

1. 重新启动，F6 后确认登场与操作正常。锁定敌人，观察默认原版逻辑下的朝向与移动；再取消锁定比较。请描述 A/S/D 时兽体是否转向、是否位移，而非只看镜头。
2. 站立 F7：应播放短退场并恢复，不应在末帧停住约 8 秒。另两轮分别在普通重击刚起手时 F7、可操作后约第 14 秒起手重击等到期；应完成当前攻击再退场。
3. 尽早使用战技（避免与 15 秒到期混淆），不按 F7：应在战技自身解除通知处直接恢复，不等 15 秒，也不额外完整播放第二段退场。再试战技刚起手时 F7，应等待同一通知点。原通知约在动画播放的第 3.667 秒，停帧/变速时不按现实秒数硬切。
4. 恢复后再做两轮 F6/F7，确认可再次进入、实体清理与镜头还原正常。轻击连段/闪避简单回归即可。

## 日志与回退

退出后运行 Collect-C0010Logs.cmd；新行为日志 Saved/er-demon-beast/c0010-hks-v7.log 会记录 movement 模式、outro:active、notification=20010:1011 或 notification=3035:1011、lifecycle=done。通知日志代表看到了图转换，最终清理还需核对 DLL 日志/帧记录。

若再次卡住，等待约 10 秒让保护与日志完成，然后退出。behavior_finish_timeout 仍算失败，不能把保护恢复当作正常退场。

在游戏完全退出后运行 Restore-C0010V7.cmd，可将 DLL、资源、配置及元数据整套回到本次之前的 v6 / DLL 0.3.1。带哈希保护；手动改过配置后，先还原本包配置内容再使用。旧 Restore-C0010V3.cmd 保留更早 v2 基线，但当前应优先用 v7 回退入口；不要混用单独的资源卸载入口。

完整 c0000 变形演出、特效及 NR 引擎机制仍未完整移植。四向选项的不同资源形态、时间轴事件的实机投递、停帧/变速行为需人工验证。
